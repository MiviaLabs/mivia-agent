## Confirmed findings

### 1. `isAllowedEnvVar` — unreachable production dead code

**Invariant:** A function kept for backward compatibility with callers should either be reachable from those callers or be removed.

**Evidence:** At `internal/tools/run.go:233` (commit 673299a):

```
if exactSet != nil {
    ...new logic...
} else {
    if !isAllowedEnvVar(key) {
        continue
    }
}
```

The `exactSet` value is always set by `resolveEnvAllowlist` at line 323:

```
exactSet = make(map[string]bool, len(base))
```

`make(map[string]bool, ...)` is never nil, even when `base` is empty/nil. Every production construction path goes through `NewDefaultRegistry` → `resolveEnvAllowlist` → non-nil `exactSet`. The `else` branch at line 253 is syntactically present and compiles, but no production call reaches it.

The function `isAllowedEnvVar` at line 353 is reachable only from the test `TestFilterEnvPackageLevelGone` which deliberately constructs `&runCommandTool{}` without setting `envExact`.

**Reachable path:** None from production code. Only direct test construction reaches it.

**Impact:** A contributor maintaining the env allowlist might add an entry to `isAllowedEnvVar` (thinking it's live), or worse, rely on its fallback behavior when it doesn't fire. The function's presence creates a false safety net.

The commit message for `3ce279f` says the function is "kept for backward compatibility with direct callers" — but at 673299a no production direct caller exists. The only callers are tests.

### 2. `basePrefixes` — dead variable in `resolveEnvAllowlist`

**Invariant:** A declared variable should be assigned before use, or not exist.

**Evidence:** At `internal/tools/run.go:294` (commit 673299a):

```
var base, basePrefixes []string
```

`basePrefixes` is declared alongside `base` but never assigned. It is consumed at line 336:

```
allPrefixes := append(basePrefixes, extraPrefixes...)
```

Since `basePrefixes` is always nil, `append(nil, extraPrefixes...)` returns `extraPrefixes` directly. The variable has no effect. It is a leftover from when `DefaultEnvAllowlistPrefixes` existed (removed in commit `3ce279f`).

**Reachable path:** Every call to `resolveEnvAllowlist` hits this code — but the dead variable causes no functional failure. The result is correct because `basePrefixes` is nil and `append` from nil is a no-op.

**Impact:** Cosmetic dead code. Increases cognitive load for future readers. No runtime failure.

### 3. Load-bearing tests specified in plan 04 §7 were never written

**Invariant:** Tests described in plan 04 §7 as "new tests" that serve as mutation proofs in the plan's verification table (§7, "Mutation proofs") should exist in the repository, or the plan should acknowledge they are unimplemented.

**Evidence:** Plan file `.mivia/plans/04-workspace-namespace-mivia.md` at lines 133-136 lists:

```
- `TestWorkspaceIgnoresLegacyAIDir` — a workspace containing `.ai/agent-prompt.md`
  and `.ai/skills/` and **no** `.mivia/` yields the compiled default prompt and
  an empty skill registry.
- `TestAgentCanEditLegacyAIDir` — `.ai/` is ordinary content: `write_file` into
  it succeeds, proving it was not made a protected path by accident.
```

The mutation-proof table at lines 142-144 uses these as guards:

```
| M1 | Add a `.ai/` fallback when the `.mivia/` file is absent |
        `TestNoHardcodedLegacyNamespace`, `TestWorkspaceIgnoresLegacyAIDir` |
| M3 | Add `.ai/` to the protected patterns |
        `TestAgentCanEditLegacyAIDir` |
```

Neither `TestWorkspaceIgnoresLegacyAIDir` nor `TestAgentCanEditLegacyAIDir` exist as Go test functions anywhere in the repo at commit 673299a. Only `TestNoHardcodedLegacyNamespace` (M1's second guard) and `TestIsSecretPathUnconfiguredFiltersNothing` (M2's guard) were implemented.

**Reachable path:** None — these are missing tests, not code paths. The gap is static.

**Impact:**

- **M1** (adding a `.ai/` fallback when `.mivia/` is absent): Only `TestNoHardcodedLegacyNamespace` guards against this. But that test only catches the literal string `.ai` in Go source code — it does not test runtime behavior. A fallback implemented purely at runtime (e.g., a forgotten `os.Stat` + fallback in `AgentPromptPath`) would pass the test but silently reintroduce the `.ai` namespace. `TestWorkspaceIgnoresLegacyAIDir` would have caught this.

- **M3** (making `.mivia/` a protected path): There is no test at all. If a future change added `.mivia` to the secret-path patterns or the `isSecretPath` exceptions, no test would catch the regression. Workspace config would become silently unreadable.
